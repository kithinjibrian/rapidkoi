## Summary

Rapidkoi is a native app for running apps: every app lives at an address, every screen has a link, and opening a link lands you in that app at that exact screen and state. Apps are signed WebAssembly bundles that describe their interface as a component tree; Rapidkoi renders it and provides accessibility, permissions, storage, sync, live sessions and history to every app. It is a personal project aiming for the best features of any app platform.

## Key Findings

- The shell (the Rapidkoi app) is what this repository builds. Guest apps are separate WebAssembly bundles, written in any language.
- Guests are sandboxed and start with no access to anything; every resource comes through Rapidkoi, only when granted.
- Guests describe *what* is on screen (a tree of meaningful components); Rapidkoi decides *how* it looks. Custom components and a canvas are the escape hatches.
- Links: `rapidkoi://{app}[@version]/{route}[/~platform…][?view state][#anchor]`. The app owns route, `?` and `#`; Rapidkoi owns `@` and every `~` segment. Web form: `https://open.rapidkoi.app/{app}/{route}`.
- Bundles are content-addressed and signed with a key tied to the publisher's domain; manifests list name, publisher, version, routes, capabilities, code fingerprint.
- Platforms: desktop (Linux, macOS, Windows) and Android first; iOS uncertain.
- Build path, in order: 1 the shell, 2 links, 3 a real app (notes or tasks), 4 storage and sync, 5 live sessions, 6 history.

## Implications for the Project

- Step 1 is the only work in scope now: a desktop app that loads a WebAssembly bundle and renders a few basic components. Links, manifests, signing, storage, sync, live sessions and history are later steps and must not leak into step 1's PRPs.
- The shell is Lugha + kivuli on GTK 4. Guest view trees are translated into kivuli `View`s, so kivuli does the rendering and diffing.
- Running downloaded code makes the WebAssembly host the project's main security boundary. Every host function exposed to guests is a capability and needs human review.
- The guest↔host UI contract (how a bundle hands over its view tree and receives events) is the core API of the platform and is hard to change later.

## Conflicts With

- kivuli renders to GTK 4, so the shell is desktop-only (Linux first) as built. Android would need another renderer. Not urgent: logged as DECISION-007 (deferred).

# Rapidkoi

**Sharing an app is as easy as sharing a link.**

Rapidkoi is a native app for running apps. Every app lives at an address, and every screen inside an app has a link. With Rapidkoi installed, tapping a link takes you straight into the app, at the exact place and state the link points to.

Rapidkoi is a personal project. Its goal is simple: to have genuinely the best features of any app platform, and to be a joy both to use and to build on.

---

## The idea

The unit of Rapidkoi is the app, and what people share is a place inside an app: a document, a filtered view, a conversation, a form waiting to be signed, or a live session in progress. A link carries the app, the screen, and the state together, so the person receiving it lands exactly where the sender meant.

Rapidkoi takes care of what all apps need: rendering, input, accessibility, sign-in, permissions, storage, sync, and live collaboration. Developers focus on what makes their app useful, and people get apps that feel fast, safe, and familiar from the first tap.

---

## Signature features

**Links to exact state.** A link opens an app at a specific screen, with its filters, layout, and position intact.

**Live sessions.** Share a live link and everyone who opens it is in the same app state together, seeing each other's changes as they happen. Every app gets multiplayer from the platform.

**Offline by default.** Kept apps run without a connection. Changes are stored locally and sync when the device is back online.

**Time travel.** Rapidkoi keeps the history of an app's state, so any screen can be viewed as it was at an earlier point, and snapshots can be shared as links.

**Fast opening.** Apps are small, cached bundles. Once an app has been opened, it starts again almost immediately.

**Inspectable apps.** Anyone can open a panel showing an app's interface structure, its permissions, what it has accessed, and which servers it has contacted.

**Your data, across apps.** A person's contacts, calendar, files and tasks aren't locked inside each app. An app asks to pick a contact or an event, Rapidkoi shows its own picker, and the app receives only what the person chose. (Added 2026-10-31, DECISION-078.)

**Accessibility and personal settings everywhere.** Every app follows the person's text size, contrast, language, and dark-mode preferences, and works with keyboards and screen readers.

---

## Links

Every Rapidkoi link has the same shape:

```
rapidkoi://board.acme.com@2.4/sprint/3/~live/k7f2xq?view=kanban#card-41
└──┬───┘   └─────┬──────┘└┬─┘└───┬───┘└─────┬─────┘└─────┬────┘└───┬───┘
 scheme         app    version  route   platform part  view state  anchor
```

The app owns the route, the view state after `?`, and the anchor after `#`. Rapidkoi owns the version after `@` and every segment starting with `~`. Platform features therefore work the same way in every app, and apps never need to handle them.

| Purpose | Example |
|---|---|
| Open an app | `rapidkoi://notes.acme.com` |
| Open a screen | `rapidkoi://notes.acme.com/folder/42` |
| Open with view state | `rapidkoi://mail.acme.com/inbox?filter=unread&sort=newest` |
| Jump to a spot | `rapidkoi://notes.acme.com/doc/77#heading-pricing` |
| Start an action | `rapidkoi://mail.acme.com/thread/881!reply` |
| Join a live session | `rapidkoi://board.acme.com/sprint/3/~live/k7f2xq` |
| Open a snapshot | `rapidkoi://board.acme.com/sprint/3/~snap/9b1e4c` |
| View a past state | `rapidkoi://notes.acme.com/doc/77/~at/2026-10-15T09:00` |
| Accept an invite | `rapidkoi://board.acme.com/sprint/3/~invite/q81mz` |
| Read-only invite | `rapidkoi://board.acme.com/sprint/3/~invite/q81mz/~readonly` |
| Pin a version | `rapidkoi://notes.acme.com@2.4/doc/77` |
| Pin an exact build | `rapidkoi://notes.acme.com@sha256:4f9a2c…/doc/77` |
| Local development | `rapidkoi://localhost:4000/folder/42` |

Every Rapidkoi link also has a web form for sharing in chats, email, and QR codes. If Rapidkoi is installed, it opens the app. If not, it shows a short page describing the app, its publisher, and how to get Rapidkoi, so a link never leads nowhere.

```
https://open.rapidkoi.app/notes.acme.com/folder/42
```

Apps can declare redirects for renamed routes so older links keep working. Live and invite links can be given an expiry.

## How it works

### Apps and bundles

Each app address points to a small, signed **manifest** listing the app's name, publisher, current version, routes, the capabilities it needs, and a fingerprint of its code.

The code arrives as a **bundle**, compiled and signed by the publisher and identified by its contents. As a result:

- an app already on the device opens without downloading anything,
- everyone running a given version runs exactly the same code,
- updates are shown to the person, and an app can be rolled back to its previous version.

Publishers sign bundles with a key tied to their domain, so the app at `notes.acme.com` is verifiably published by whoever controls that domain. Rapidkoi always shows an app's verified address in a place apps cannot draw over.

### The runtime

Bundles are compiled to WebAssembly, so apps can be written in many languages, including Rust, Go, Kotlin, Swift, C#, and C++.

Apps run in a sandbox and start with no access to anything. The network, files, camera, location, and other resources are only available through Rapidkoi, and only when granted. Each app runs separately from Rapidkoi itself, so a faulty app is contained.

### The interface

Apps describe their interface as a tree of meaningful components, and Rapidkoi renders it.

```rust
fn inbox(state: &Inbox) -> View {
    Screen::new("Inbox")
        .toolbar([Action::new("Compose", Icon::Pencil, on_compose)])
        .body(
            List::new(&state.messages, |m| {
                Row::new()
                    .title(&m.subject)
                    .subtitle(&m.sender)
                    .badge_if(m.unread, "New")
                    .on_open(route!("/message/{}", m.id))
            })
            .searchable("Search mail")
        )
}
```

The app says *what* is on screen. Rapidkoi decides *how* it looks and behaves on the device in hand. Because Rapidkoi understands every part of the interface, it can provide accessibility, personal settings, consistent search and selection, adaptive layouts, live sessions, and time travel to every app.

The component library covers screens, navigation, tabs, lists, tables, forms with typed fields, dialogs, menus, rich text, media, charts, and maps. **Layout** uses stacks, grids, and constraints. **Themes** let each app set its colours, typeface, shape, and density, while the person's own settings always take precedence.

**The trade-off.** Describing an interface instead of drawing it means apps give up some control over exactly how they look and behave. Rapidkoi offers two ways to go further:

- **Custom components**, built by an app from smaller parts, which still describe their meaning so they keep accessibility and the other platform features.
- **Canvas**, a free drawing surface for games, design tools, and visualisations. A canvas carries a description for accessibility, but it does not get the full set of platform features.

The richer the component library, the less often apps need either.

### Built-in services

- **Identity.** People sign in to apps with a single approval, using passkeys held by Rapidkoi. Each app receives an identifier unique to that app.
- **Storage.** Each app has private, structured storage on the device.
- **Sync.** An app's storage can sync across a person's devices with end-to-end encryption. Apps with their own servers sync with those instead.
- **Live state.** Rapidkoi connects the participants in a live session and keeps their shared state consistent.
- **History.** State changes are recorded so they can be undone, viewed at an earlier time, or shared as snapshots.
- **Data ownership.** People can export an app's data, and removing an app removes what it stored on the device.
- **Shared data.** Common kinds of personal data (contacts, events, files, tasks) have shapes every app understands. Apps read or add to them only with the person's consent, given in Rapidkoi's own screens, so people move between apps without exporting and developers don't rebuild the same data. (Added 2026-10-31, DECISION-078.)

### Permissions

An app declares what it needs in its manifest: network access to named servers, camera, microphone, location, notifications, or background work. People see these in plain language before an app first runs.

Sensitive access is granted at the moment it's needed, through Rapidkoi's own screens. When an app asks to open a file, Rapidkoi shows the file picker, and the app receives only the file the person chose. Apps run only the code in their signed bundle and can only contact the servers they declared.

### Publishing

Anyone can publish a Rapidkoi app without approval. A developer builds the bundle, signs it with their key, and places the manifest at their domain. Publishers ship updates whenever they choose.

## The Rapidkoi app

The Rapidkoi app is where people open, keep, and manage their apps.

- **Open** apps from links, by address, or by search.
- **Keep** apps on the device, ready to launch offline.
- **Share** any screen, snapshot, or live session with one button.
- **Navigate** with back and forward, which follow each app's routes.
- **Review** each app's permissions and activity in one consistent panel.
- **Rewind** any screen to an earlier state.

Extensions can add features across all apps through the interface tree, such as filling in passwords or translating text, each with clearly stated permissions and no access to an app's internals.

---

## Building for Rapidkoi

- Write apps in the language you prefer, with the Rapidkoi UI library for it.
- Run a development server at `rapidkoi://localhost`, with live reloading.
- Inspect the running interface tree, state, history, permission use, and performance.
- Build, sign, and publish with one command.

One rendering specification and one conformance test suite mean an app behaves the same everywhere Rapidkoi runs.

---

## Platforms

Rapidkoi is built for desktop (Windows, macOS, and Linux) and Android first. iOS support depends on finding a path that fits Apple's rules for running downloaded code.

---

## Build path

1. **The shell.** A desktop app that loads a WebAssembly bundle and renders a few basic components.
2. **Links.** `rapidkoi://` addresses that open an app at a given route and state.
3. **A real app.** A notes or tasks app built only on Rapidkoi, to shape the component library.
4. **Storage and sync.** Offline storage that syncs between devices.
5. **Live sessions.** Shared, real-time state from a link.
6. **History.** Time travel and shareable snapshots.
