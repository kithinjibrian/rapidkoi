# Apps reaching the network (PRP-012) — design in chat, session 62, 2026-10-19

The owner and Claude, one topic at a time; each answered "yes". It builds on the signing-and-panel talk (2026-10-18): network access is declaration-only (named servers, no prompt), listed in the panel, switchable, per app (host and key).

## 1. Which servers — settled

- Listed by the developer in `rapidkoi.toml`: `[network] servers = ["api.notes.acme.com", …]`. `publish` puts them in the signed manifest, so no server can be added without re-signing.
- The app's own host is always allowed without listing.
- Names only, HTTPS only. Plain `http://localhost` is allowed in development, and only for apps from this machine (a local file or a local address): a remote app can never reach your localhost (found while writing the PRP).
- Anything else is refused with a reason the app gets back; the request never leaves the computer.
- The Access page lists them: the app's own host, then the declared ones.

## 2. What an app can do — settled

- A `fetch` effect: method (GET, POST, PUT, PATCH, DELETE), URL, headers, body. It's sent in the background. The answer is `{status, headers, body}` or `{error}`.
- No cookie jar (an app keeps its own token in its state). No redirects followed (the app gets the 3xx).
- Limits: 30 s per request, 1 MB up, 8 MB down, a few requests in flight per app.
- Errors are plain sentences. WebSockets later.

## 3. Signing in to the app's server — settled

- No special signed fetch: the app does fetch the challenge → `sign` → fetch the signature (identity, PRP-011). Rapidkoi never holds the app's tokens.
- The Rust library gets a small helper for the three steps. Server developers get an exact description of what to check (a server library later).
- Signed out in the Account page means `sign` gets nothing, so the server sees no proof: signing out works for every app.

## 4. Updates and switches — settled

- An update that adds a server is allowed without a prompt (the same key, so the same publisher; a changed publisher is caught by the key check). A one-time notice says "Notes can now also reach X", and the Access page marks it new until seen.
- Per-server off switches on the Access page, the own host included. A switched-off server is refused with "You turned off X for Notes". They're remembered, and cleared by Forget.
- A server removed in an update is simply no longer on the list.
