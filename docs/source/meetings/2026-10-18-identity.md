# Identity — design in chat, session 55, 2026-10-18

The owner and Claude, slowly, one question at a time (with ASCII pictures in chat). Feeds a future PRP (accounts, DECISION-022). Authentication: the owner's security review at every step (CLAUDE.md security rule).

## The problem — settled

- Apps that live only on the device don't need to know who you are (each app's state is already private to it).
- Apps with a server do: the server must recognise the same person again, and be sure of it, without passwords. That's all identity means here.

## Each app sees a different person — settled

- Rapidkoi makes one key pair per app (per app identity: host and key). The private key never leaves the device; the app's server gets only the public key.
- Sign-in: the server sends a fresh random challenge; Rapidkoi signs it together with the host (so a fake site can't borrow a real sign-in); the server checks it with the public key it saved.
- Two apps get unrelated keys, so they can't tell they share a person.
- A site that changes owner and is opened as a separate app gets a new key pair: the new owner sees a new person and can't take over the old account.

## What the app learns — settled

- Only the public key. No name, email or phone from Rapidkoi.
- A display name the app needs can be a placeholder from the key (e.g. "User 4f9a"), or something the app asks for in its own screens.

## Parked

- **Name placeholders** (the owner's idea): the app writes `{NAME}` in display text and Rapidkoi fills it in while drawing, so the app can show your name but never know it. Text nodes only (not text boxes), nothing sent back contains it; needs UI contract v2.
- **Email and phone:** the app asks in its own screens and you type it (option A). Later, optionally: autofill, and connecting your own email-forwarding service (Firefox Relay, SimpleLogin, addy.io) for a new address per app. The relay's API key is a secret (security review); phone masking APIs to be checked.

## No 2FA needed — settled

- Keys aren't typed, aren't reused, can't be phished (the host is in what's signed) and don't leak from a hacked server (it holds public keys only). The second factor is the device itself, plus optionally its unlock (PIN, fingerprint) before serious actions.

## Auto sign-in — settled ("yes auto sign-in on by default")

- On by default: the first time an app asks, Rapidkoi makes its key pair and answers, with no prompt.
- The cost (the app's server can recognise you across visits, like its own cookie) is accepted; cross-app tracking stays impossible.
- The Account page: "Signed in as User 4f9a"; Sign in automatically (on); Sign out (same key when you return); Start over as someone new (a fresh key pair, asks first).
- Rapidkoi signs only when the app asks, always with the host.

## Recovery — designed, built later

- One master secret; every app's key is derived from it and the app's identity, so backing up one thing restores every app. Shown later as 12 recovery words; device-to-device sync with the sync step.
- Keys come from the master from day one (so recovery later doesn't change anyone's key). Needed `hkdf_sha256` in std: added (Lugha m120).

## Build now — settled ("let's build first what we have. the keys + placeholders(FIRST_NAME, LAST_NAME)")

- Per-app keys (auto sign-in), and `{FIRST_NAME}` / `{LAST_NAME}` placeholders. Apps can't reach their server yet (no network capability), so in this step an app can ask for its public key and for a signature; using them with a server comes with that capability.
- The name: one for every app, optionally one per app, empty by default. Contract v2.
